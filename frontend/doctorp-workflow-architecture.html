1. 🏛️ High-Level System Architecture

DoctorP follows a strict Model-View-Controller (MVC) architectural pattern to decouple clinical data persistence, HTTP business routing, and the patient/doctor UI tier:

  • Presentation Tier (Views): Responsive vanilla HTML5/CSS3/JavaScript modules with real-time UI components, simulated Razorpay/UPI checkout sheets, and printable digital clinic desk passes.
  • Routing & Security Middleware: Centralized Express router equipped with JWT bearer authentication, role-based authorization (patient, doctor, admin), Helmet HTTP security headers, CORS origin management, and proxy-aware rate limiters.
  • Business Controller Layer: Encapsulates atomic conflict detection, real-time 5-minute slot reservation locks, simulated payment capture, and automated rating aggregations.
  • Data Tier (Models): High-performance MongoDB Mongoose schemas with compound unique indexing, pre-save hooks, password encryption via bcryptjs, and virtual schema properties.

2. 👤 Patient Operational Workflow

The patient journey follows a frictionless 5-stage lifecycle from discovery to consultation review:

Step 1: Clinical Discovery & AI Triage

Patients search verified doctors by department, location, and fees, or enter conversational symptoms into the AI Symptom Checker to receive urgency scoring (High/Medium/Low) and clinical specialty recommendations.

Step 2: Real-Time Slot Availability & 5-Minute Hold

Patients inspect live schedule slots (Morning, Afternoon, Evening). When a slot is selected, POST /api/doctors/slots/lock holds the slot for 300 seconds to prevent double-booking across concurrent browser sessions.

Step 3: Secure 256-Bit Payment Gateway Checkout

The integrated payment modal allows patients to pay via BHIM UPI/QR code, Credit/Debit card, Net Banking, or opt to "Pay at Clinic". Payment capture issues unique TXN-XXXX and REC-XXXX transaction receipts.

Step 4: Atomic Appointment Booking & Digital Desk Pass

Upon payment confirmation, POST /api/appointments generates a permanent tracking record (APT-XXXX). The patient immediately receives a Printable Digital Pass & QR Desk Token, downloadable .ics calendar invite, and WhatsApp share shortcut.

Step 5: Post-Consultation Reviews & Prescription Records

After completing the consultation, patients submit 1-5 star ratings that automatically update the doctor's average rating in MongoDB Atlas and access electronic prescription slips.

3. 👨‍⚕️ Doctor Clinical Workspace Workflow

  • OPD Queue Sequencer: Doctors log into their dedicated workspace to view patient arrivals and click "🔔 Call Next Token" to progress clinic consultations.
  • Telehealth Video Suite: Peer-to-peer WebRTC consultation room with audio/video streaming and signaling mediated by /api/telehealth/signal.
  • Electronic Medical Prescriptions: Doctors generate branded prescription slips with clinical diagnoses, drug dosages, and clinical instructions.
  • Schedule & Slot Scheduler: Doctors configure working days, morning/evening shifts, consultation duration, and batch-generate slots.

4. 👑 Administrator Governance Workflow

  • Doctor Verification & Approvals: Administrators inspect medical council registration numbers (DMC/MMC) and verify clinical licenses before doctors appear in public searches.
  • Platform Analytics: Real-time oversight over total consultations booked, revenue metrics, appointment completion ratios, and cancellation logs.
  • User & Audit Management: Ability to view registered patients, manage doctor permissions, and resolve clinical scheduling disputes.

7. 🗄️ Core Database Schemas

Appointment Schema (`Appointment.js`)

const appointmentSchema = new mongoose.Schema({
  appointmentId:    { type: String, unique: true, index: true }, // e.g. APT-20261031-8421
  doctorId:         { type: mongoose.Schema.Types.ObjectId, ref: 'DoctorProfile', required: true },
  patientId:        { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  appointmentDate:  { type: String, required: true }, // YYYY-MM-DD
  startTime:        { type: String, required: true }, // HH:mm
  endTime:          { type: String },                 // HH:mm
  consultationType: { type: String, enum: ['In-Clinic Visit', 'Video Consultation'], default: 'In-Clinic Visit' },
  reason:           { type: String, default: 'General Consultation' },
  status:           { type: String, enum: ['pending', 'confirmed', 'rejected', 'cancelled', 'completed'], default: 'pending' },
  fee:              { type: Number, required: true, default: 500 },
  paymentStatus:    { type: String, enum: ['pending', 'paid', 'refunded', 'pay_at_clinic'], default: 'paid' },
  paymentMethod:    { type: String, default: 'UPI / Online' },
  transactionId:    { type: String }
}, { timestamps: true });

Payment Schema (`Payment.js`)

const paymentSchema = new mongoose.Schema({
  paymentId:      { type: String, unique: true, index: true }, // PAY-XXXX-XXXX
  orderId:        { type: String, index: true },               // ORD-XXXX-XXXX
  patientId:      { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  doctorId:       { type: mongoose.Schema.Types.ObjectId, ref: 'DoctorProfile' },
  amount:         { type: Number, required: true, min: 0 },
  currency:       { type: String, default: 'INR' },
  paymentMethod:  { type: String, default: 'UPI / Online' },
  status:         { type: String, enum: ['created', 'pending', 'paid', 'failed', 'refunded', 'pay_at_clinic'] },
  transactionId:  { type: String, unique: true, sparse: true },
  receiptNumber:  { type: String, index: true },
  paidAt:         { type: Date }
}, { timestamps: true });
